## Data

### highLevelPlan

- Add exactly one new internal package — `presentation-feature-mirror/core/payload/` — holding every pure function this feature needs (prompt assembly, the 360+count*140 estimator, the (1.6+count*0.12) MB label, the crop window transform, the hierarchy-row projection, the source/footer labels). This is the only layer the repo's harness can test (testing.md), and it is the module's fourth `core/` package after `geometry`, `annotation`, `measure` — the precedent is already set (FR-47..FR-51, AC-72..AC-78).
- Add one new public composable — `source/mirror/MirrorPayloadTab.kt` — the sibling of the shipped `MirrorNotesTab`: stateless, reads `MirrorUiState` + the frozen bitmap + the cached `HierarchySnapshotModel`, places strings the pure layer already formatted, and renders the three sections plus footer (FR-12..FR-15).
- Join the tab strip by adding a single `if (tab == ShellTab.Payload)` branch to `RectifyWindow.kt`'s existing `sidePanel = { tab -> … }` lambda. `ShellTab.Payload`, `shortcutToTab(Cmd+2)`, `SidebarTabs` and `SidePanelFrame` all already ship and need no change — the tab exists and is empty today, so this is one branch, not any new chrome.
- Expose the already-cached hierarchy to the panel by widening `MirrorHost`'s content lambda from `(state, frame, onIntent)` to `(state, frame, hierarchy, onIntent)` — one call site. Payload-preview reads `MirrorViewModel.frozenHierarchy` and never triggers a dump (AS-22, AC-74); the badge projection is derived in a `remember`, so hundreds of nodes still never enter the reduced state (the module's documented Deviation 2).
- Mint the freeze counter where the freeze actually happens: a `private var freezeCounter` on `MirrorViewModel`, incremented in `stageAnnotation`'s intent body (NOT inside `reduce`, whose lambda can re-run on a lost race per its own KDoc), stamped onto the new `FrozenFrame.frameId`. The same freeze stamps `FrozenFrame.deviceLabel` so the prompt's device line survives a device drop (FR-52, FR-55).
- Carry the edited prompt on `FrozenFrame.promptOverride: String?` so it dies with the pinned frame automatically at every site that already nulls `frozen` (resumeLive / stopSession / selectPlatform) and persists across tab switches until the user edits again (AC-79, FR-53).
- Render crops with one `Canvas { drawImage(image, srcOffset, srcSize, dstOffset, dstSize) }` per annotation instead of porting the design's negative-margin/`transform: scale()` CSS — Compose crops and scales in one call, so the pure `cropWindow(...)` only has to return source rect, container size and the outline rect (AC-76, FR-49).
- Reuse the shipped-but-callerless `HierarchyRow` molecule for the tree, with one additive `matched: Boolean` parameter so it can colour ink vs ink3; its `tag` badge already defaults to `Theme.color.annotate`, which is the design's red (AC-75, AS-24).

### proposedArchitecture

```
Two layers in one module, plus two one-line edits outside it. No new Gradle module, no new dependency, no new data source — every byte this feature shows already exists in `MirrorUiState`, `MirrorViewModel.frozenFrame` and `MirrorViewModel.frozenHierarchy`.

1. PURE LAYER — `presentation-feature-mirror/src/commonMain/.../core/payload/` (internal, per package-layout.md: `core/` is internal-only). Nothing here imports Compose beyond `IntSize`/`IntOffset`, nothing imports Orbit, so every AC with a formula or a format in it becomes a `commonTest` assertion. This is the load-bearing decision of the spec: `:compose-application` has no test wiring (testing.md), so anything stranded in the window layer or inside a `@Composable` is unverifiable by construction.
   - `PromptAssembly.kt` — `buildPrompt(frozen: FrozenFrame, deviceLabel: String, nodeIdFor: (StagedAnnotation) -> String?): String`. Ports the design's `pl[]` exactly: headline with the `count === 1` plural branch, the device line from real data (FR-52), then per annotation `#{i} {nodeId} · {w}×{h}` + the comment verbatim in quotes (or `no comment`), then the `Attached: frame.png, N crops, hierarchy.xml` trailer. **No `measured:` branch** — AS-26/AC-73: measure-mode already folded the `⌥` line into `comment`, so the comment is printed verbatim and the design's third `pl.push` has no counterpart. Reuses `core/annotation`'s `TIMES` constant (already `internal` for exactly this reason) so the module keeps one `×` (AC-72).
   - `PayloadEstimate.kt` — `tokenEstimate(count: Int): Int = 360 + count * 140`, `payloadSizeLabel(count: Int): String` and `footerLabel(count: Int): String`. One decimal is formatted by hand (`(value * 10).roundToInt()` then `tenths/10`.`tenths%10`) because `String.format` is not in the common stdlib — the `core/stats/formatFps` precedent, which should be promoted to a shared internal `oneDecimal(...)` rather than copied, so the two places that round cannot disagree (FR-48, FR-51, AC-78).
   - `CropWindow.kt` — `cropWindow(rect: DeviceRect, frameSize: IntSize, boxW: Int = 84, boxH: Int = 72, pad: Int): CropWindow`. The design's `crop()` with the hardcoded `296`/`640` generalised to the real frame: `cx = max(0, x-pad)`, `cw = min(frameW-cx, w+2*pad)`, `s = min(boxW/cw, boxH/ch)`. Returns source rect (device px), container size, scale, and the outline rect in container coordinates — which is what AC-76 pins. The design's `fixed` flag is dropped: it is `false` at this call site and the design's own function only stores it.
   - `HierarchyOutline.kt` — `payloadHierarchyRows(snapshot, frozen, frameSize): List<PayloadNodeRow>` where `PayloadNodeRow(nodeId, depth, last, badge: String?, matched: Boolean)`. Runs the existing `projectMeasureNodes` + `snapTarget` per annotation (AC-75 says badge iff `snapTarget` matched, so the badge must come from the same function measure-mode uses, not a second containment rule), builds an index-to-node map, then maps `snapshot.nodes` once. `last` is computed from the next row's depth, which is all `HierarchyRow`'s guide drawing needs.
   - `PayloadLabels.kt` — `hierarchySourceLabel(status, nodeCount)`: the design's phase machine reduced to the four `HierarchyStatus` values this repo already ships — `Dumping` → `dumping…` (warn), `Ready` → `uiautomator · {n} nodes` (AC-74), `Absent`/`Unavailable` → the explicit no-hierarchy state (AC-80). No new enum, no new status (confirmed constraint).

2. RENDER LAYER — `source/mirror/MirrorPayloadTab.kt` (public, the `MirrorNotesTab` precedent exactly: public composable, `state`/`onIntent`, `@Preview` pairs, every piece of localisable copy through `stringResource`). Private section composables in the same file (`PayloadPromptSection`, `PayloadCropsSection`, `CropThumb`, `PayloadHierarchySection`, `PayloadFooter`) — fewest files, and none of them is reusable kit: they are this tab's layout.
   - Gate first: `annotations.isEmpty()` → the single empty-state `Text` and `return`, so Prompt/Crops/Hierarchy/footer are *not composed at all* (FR-54/AC-77 — the design's own `count === 0` gate, and the same early-return shape `MirrorNotesTab` already uses).
   - Everything derived is `remember(...)`-keyed on its real inputs: the prompt on `(frozen.annotations, frozen.deviceLabel, hierarchy)`, the crop windows on `(annotations, frozen.deviceSize)`, the rows on `(hierarchy, annotations)`. Arithmetic therefore runs on change, not per frame, and AC-78's "synchronously, no lag" is satisfied by O(1) formulas rather than by a budget anyone has to measure.
   - Crops: `LazyVerticalGrid`-free — a fixed 3-column layout is three `Row`s of `Modifier.weight(1f)` cells (the design's `repeat(3, minmax(0,1fr))`), each a 72 dp-high `Box` on `Theme.color.stage` containing one `Canvas` that `drawImage`s the source rect into the container rect, plus a 1 px `Theme.color.annotate` outline box at `CropWindow.outlineRect`. Caption `#{i} · {w}×{h}` from the annotation's own raw pixel dimensions (FR-49, AC-72).
   - Hierarchy: a `LazyColumn` with **no vertical arrangement spacing** (HierarchyRow's KDoc makes this load-bearing — its tree guides only meet when rows are adjacent) over `payloadHierarchyRows`, inside the panel's bounded height. A real dump is ~400 rows; a plain `Column` + `verticalScroll` would compose 400 molecules each with their own `Canvas`.
   - Prompt: read-only mono `Text` on `Theme.color.codeBg` with a `Theme.color.line` hairline and a max height, or — when the user has clicked Edit — the shipped `MultilineInput` atom seeded with the current prompt, dispatching `MirrorIntent.EditPrompt(text)` on change (the `CommentAnnotation` precedent: typing already goes through this reducer, at typing rate, not 60 Hz). The read/edit toggle itself is `remember`-local view state; the *text* is reduced, because it changes what gets sent.

3. STATE — three small additions, no new state home. `FrozenFrame` gains `frameId: Int`, `deviceLabel: String` and `promptOverride: String?`; all three describe the pinned frame as it was at freeze, all three are value-equal, and all three are destroyed for free wherever `frozen` is already nulled. `MirrorIntent` gains `EditPrompt(text: String)` (one handler, one `reduce`). `MirrorViewModel` gains `private var freezeCounter: Int` incremented in `stageAnnotation`'s intent body before `reduce`. `MirrorUiState` itself gains nothing — the Payload tab is a projection of state that already exists, which is why this spec adds no reduced field at all.

4. OUTSIDE THE MODULE — `MirrorHost`'s content lambda gains the hierarchy parameter (one definition, one call site), and `RectifyWindow.kt`'s `sidePanel` lambda gains an `else if (tab == ShellTab.Payload)` branch plus `ShellTab.Payload to mirror.stagedCount` in `tabCounts`. That is the whole of "joining the tab strip": `SidePanelFrame`, `SidebarTabs`, `ShellTab` and `shortcutToTab` are untouched.
```

### exceptions

- Zero staged annotations: the tab early-returns on the empty-state copy before any section composes, so no formula, no crop, no row and no footer runs at all (FR-54, AC-77, SC-20).
- `HierarchyStatus.Unavailable` or `Absent` with annotations staged: `hierarchySourceLabel` returns the explicit no-hierarchy state, the row list is empty, and Prompt / Crops / footer render untouched (AC-80, SC-23). The footer still says `hierarchy.xml` because the send still attaches whatever the dump produced — the Hierarchy section is where the absence is reported, not the footer.
- `HierarchyStatus.Dumping` (the ~2.7 s window after a freeze): the header reads `dumping…` in `Theme.color.warnStillOff` and the tree is empty-but-explained, reusing measure-mode's already-confirmed 'report it, don't lie' answer rather than inventing a Payload-specific one.
- No annotation snapped to any node (`snapTarget` returned null for all of them): every row renders ink3 with no badge, and the prompt's per-annotation line falls back to the design's generic node word rather than printing a dangling id (SC-21).
- Frozen bitmap is null while `frozen != null` (possible for one composition between the reduce and the flow emission): the Crops grid renders its containers on `Theme.color.stage` with no image rather than throwing or skipping the section, so the grid does not flicker its layout.
- Hierarchy snapshot geometry disagrees with `FrozenFrame.deviceSize` (rotation between capture and dump): `projectMeasureNodes` already discards it, so the badge projection sees no nodes and the section reports no hierarchy — the same handling as a failed dump, with no second mismatch rule written here.
- An annotation rect touching the frame edge: `cropWindow`'s `max(0, …)` / `min(frameSize, …)` clamps mean the crop is simply smaller on that side and the scale adjusts; the outline stays at the rect's true position inside the container.
- A degenerate (zero-area) rect cannot reach the staged list (F-4's 8 px drag floor), but `cropWindow` still guards `cw`/`ch` against zero so the unit test of the formula cannot divide by zero.
- Prompt edited, then every annotation deleted: the frame stays frozen with zero annotations, so the empty-state gate wins and the override is simply not rendered; it is still carried on the frame and reappears if an annotation is re-drawn. Deliberate — the confirmed default is 'no auto-clear'.
- Prompt edited to an empty or whitespace string: treated as 'no override' for the purpose of what gets attached (FR-53 says non-empty and changed), so the user cannot accidentally send a blank prompt by selecting-all and deleting.
- Device drops after freeze (`MirrorSession.Lost`): `deviceLabel` was captured at freeze, so the prompt's device line is unchanged; nothing in the Payload tab reads live discovery.
- Resume Live / Stop / platform switch: `frozen` is nulled at three existing sites, which takes `frameId`, `deviceLabel` and `promptOverride` with it; the next freeze gets `freezeCounter + 1`.

### edgeCases

- Crop padding is specified as `14` in a 296-px-wide design preview, i.e. ~4.7% of frame width — taken literally as 14 device pixels on a 1080-wide frame it is ~1.3% and the crops come out visually tighter than the design. Proposed: scale the pad by `frameWidth / 296` so the context around each box matches the design on any device, and keep `84`/`72` as literal container dp. This is survey question 3 and the only place AC-76's 'exactly crop(…, 14, …)' needs reading as design-space rather than device-space.
- A very large annotation (a box covering most of the screen) scales to a crop where the red outline is almost the whole container; correct per the formula, and the caption's raw `{w}×{h}` is what tells the reporter the real size.
- Annotations renumber on delete (F-4, AC-8): the crop caption index, the hierarchy badge `#n` and the prompt's `#n` all read `StagedAnnotation.index`, never a list position, so the success metric 'index-consistent across edits/deletes' holds by construction rather than by three agreeing loops.
- Two annotations snapping to the SAME node: the node can only carry one badge. Proposed: the lowest annotation index wins and the others simply have no badged node — no merged `#1 #2` badge, because `MeasureTag` is a single short label and a merged badge would need a new component.
- A node whose `resource-id` was empty (Compose surfaces) arrives from measure-mode already labelled by class name plus a sibling index — nothing new here, but the Hierarchy section is the first place a user sees dozens of them in a row, so the ellipsis and the 26 dp row height matter more than they did in the measure card.
- A deep tree: `HierarchyRow` indents 16 dp per level, so depth 12+ pushes the node text off a 300 dp panel. The text already ellipsizes; no horizontal scroll is proposed (the design has none either), and this is recorded as a known ceiling rather than solved.
- Prompt longer than the block's max height: the block scrolls and the Edit affordance stays in the section header, outside the scrolling area (the design's header/block split) — which also answers the input's open question about Edit scrolling away.
- Token estimate while editing: the formula is `360 + count*140` and nothing else, so an edited prompt does NOT change the number. That is honest only because the label says `≈ tokens`; it is called out in the gaps because a user who deletes half the prompt will expect the figure to move.
- Payload size while editing: same — the `(1.6 + count*0.12) MB` figure tracks crop count, not prompt length, which is fine because text is noise next to a PNG but is a visible inconsistency if anyone looks closely.
- Panel narrowed to its minimum width: three crop columns at ~84 dp plus gaps still fit the clamped minimum panel width, but the caption `#1 · 1035×862` will ellipsize before the image does. Accepted; the caption is the dispensable half.
- Cmd+2 pressed with nothing frozen: the tab shows the empty state, which is already the correct answer — no special 'no frame' state is invented (the design has none).
- Switching to the Payload tab mid-dump and staying there: the header is the only thing that changes when the dump lands, because the row list is `remember`-keyed on the snapshot — no full-tab recomposition, no flash.

### implementationSteps

- Add `core/payload/PayloadEstimate.kt` with `tokenEstimate`, `payloadSizeLabel`, `footerLabel`, promoting `core/stats`'s private one-decimal rounding to a shared internal helper; test the formulas at count 0/1/2/9 and the `.0`/`.1` boundary (FR-48, FR-51, AC-78).
- Add `core/payload/CropWindow.kt` + its test: clamping at all four frame edges, scale picked as `min(bw/cw, bh/ch)`, outline rect relative to the crop, and the pad-space decision from the survey applied in exactly one place (FR-49, AC-76).
- Add `core/payload/PromptAssembly.kt` + its test: the singular/plural headline, the real device line, the comment-verbatim line with the `no comment` fallback, an annotation whose comment already carries a `⌥` measurement line (AC-73 — asserting there is no second `measured:` line), and the `Attached:` trailer. ### gaps

- The crop pad's coordinate space is genuinely undetermined by the design: `14` is stated in a 296-px preview and the AC repeats the literal. Device-space and design-space differ by ~3.6× on a 1080-wide frame, and only one of them looks like the screenshot. Survey question 3.
- `frameId` has no display format: FR-55 says sequential counter, the design shows `from frame 18422` (five digits). A counter renders `from frame 1`, which is correct and looks nothing like the design. Proposed: render the bare counter; nobody has decided whether it should be zero-padded or offset.
- The token estimate and the size figure are both functions of annotation count only, so neither moves when the user edits the prompt. Defensible for the size (bytes are dominated by PNGs) and visibly odd for the tokens. The `≈` label is the whole mitigation.
- NFR-12 (versioned payload format) has no consumer in this spec — nothing sends anything yet. Proposed: declare `PayloadFormatVersion = 1` in `core/payload` now and let the send feature attach it; this spec renders nothing from it. Open decision below, because the alternative is to defer NFR-12 entirely to the send spec.
- The design's `payload` rows (Frame `1344×2992 PNG`, Hierarchy, Agent `claude · ~/code/shopkit`) are NOT in this spec's ACs and the Agent row has no data source anywhere in the repo — no agent path, no project root, no MCP config exists. Only the footer line and the hierarchy state machine are implemented; the Agent row is unbuildable today and is left out deliberately rather than stubbed with the design's literal.
- Nothing in this spec consumes the payload. The whole feature is a preview of a bundle no code assembles for real yet, so the success metric 'displayed always matches what is actually assembled' cannot be verified by anything until the send feature exists — the mitigation is that the send feature must call the same `core/payload` functions, which is a constraint on a future spec, not a test here.
- The frozen bitmap is the full-resolution screenshot; crops are drawn from it live on every recomposition of a cell. Nobody has measured ~9 simultaneous `drawImage` downscales of a 1080×2400 bitmap in a resizing panel. Likely trivial, entirely unmeasured.
- `HierarchyRow` has never had a production caller, so its 26 dp fixed row height, 16 dp indent and ellipsis behaviour have never been seen with real uiautomator node ids at real depths — only with the three hand-written preview rows.
- No Compose UI-test harness exists, so the 3-column grid, the baked outline's position, the tree guides and the empty/no-hierarchy layouts are demo-verified only (already accepted in outOfScope). Everything assertable has been pushed below the Compose layer; pixel placement itself stays unproven by any test.
- Whether `deviceLabel` should read the selected row's `detail` (`Android 15 · USB`, which carries a transport word the prompt does not want) or a dedicated `androidVersion` is undecided — `MirrorUiState` carries `selectedDeviceName` but no version, and `DeviceModel.androidVersion` is nullable. The proposal captures the row detail and strips the transport segment; a cleaner fix is a second reduced field at commit.
