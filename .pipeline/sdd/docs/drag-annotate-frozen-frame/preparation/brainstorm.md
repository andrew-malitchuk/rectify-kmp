## Data

### highLevelPlan

- Make the coordinate conversion a pure, display-free function first (FR-26) and unit-test it before any pixel is drawn — it is the only piece whose failure is silent (AC-46, SC-8).
- Extend presentation-feature-mirror's existing Orbit contract with a frozen-frame sub-state and a staged-annotation list; keep the frozen ImageBitmap OUT of the reduced state on a second StateFlow, exactly as F-2 does for the live frame.
- Freeze as a RENDER decision only: sessionDeviceId and the flatMapLatest capture gate are never touched, so 'Resume Live' needs no new adb session (FR-30).
- Assemble the visuals from shipped kit components — AnnotationMark, Ruler, CommentPopover, AnnotationPopover, AnnotationRow, CounterBadge, GlyphBadge, MeasureTag, StatusIndicator(Frozen), AppButton — and author exactly one new kit molecule (AnnotationOverlay: scrim + marks) plus one new optional slot parameter on MirrorFrameView.
- Wire the three F-1 stubs the PRD reserved for this feature: ShellToolbar.stagedCounter, ShellToolbar.clearAction, and SidePanelFrame's Notes tab (+ its tabCounts entry).
- Ship FR-9 at demo fidelity with one pure pairwise-overlap function and a straight Canvas leader line; no elbow-stagger polish.
- Hold everything in memory: no disk, no serialization, no new data module — the POC's JSON writer is F-7's and F-8's business.

### proposedArchitecture

```
Four layers, no new Gradle module.

(1) GEOMETRY — `presentation-feature-mirror/src/commonMain/.../core/geometry/FrameGeometry.kt`, internal, pure, no @Composable and no ViewModel. The key correctness insight, verified against the POC: the pointer offsets delivered by `pointerInput` and the frame box size reported by `onSizeChanged` are in the SAME pixel space, so density cancels out of the storage conversion entirely — `devicePx = pointerPx / frameBoxPx * deviceSizePx`. The POC's 2x bug came from the return leg (`Modifier.offset(dp)` re-multiplying by density), not the storage leg. The file therefore exposes a `FrameGeometry(framePx: Size, deviceSize: IntSize, density: Float)` value class with three pure members: `toDevice(start: Offset, end: Offset): IntRect` (normalises reversed drags, clamps to device bounds, rounds both corners rather than the size so the rect cannot drift), `toFrame(rect: IntRect): Rect` (device px -> frame-local px, for rendering), and `Rect.toDpRect()` (frame px -> dp via the supplied density, the single place density is ever applied). Everything downstream calls these three; no call site does arithmetic of its own. Canonical storage space = device screenshot pixels, held as an `IntRect`-shaped model on the annotation.

(2) STATE — `presentation-feature-mirror`, Orbit, existing four-file contract extended (no new feature module; see alternatives). `MirrorUiState` gains `frozen: FrozenFrame?` where `FrozenFrame(deviceSize: IntSize, annotations: List<StagedAnnotation>, selectedIndex: Int?)` and `StagedAnnotation(index: Int, rect: DeviceRect, comment: String)`. Annotations DO belong in the reduced state and the live bitmap does not, for opposite reasons: annotations are a handful of small value-equal records mutated only by discrete user actions, read simultaneously by the toolbar badge, the Notes tab and the stage — which is precisely the job of reduced state; frames are identity-compared blobs arriving ten times a second. The frozen bitmap itself is the same kind of object as a live frame, so it is published on a second `StateFlow<ImageBitmap?> frozenFrame` beside `frame`, and the reducer only ever stores the frozen frame's `deviceSize` (two Ints) — which is all the reducer, the meta lines, the Ruler extent and the geometry function actually need. `MirrorStage` gains a `Frozen` value derived from `frozen != null` (ordering: Picker > IosDeferred > Frozen > Mirror > NoSignal). New intents: `StageAnnotation(rect)`, `SelectAnnotation(index?)`, `CommentAnnotation(index, text)`, `DeleteAnnotation(index)`, `ClearStaged`, `ResumeLive`.

(3) FREEZE — purely a render-path switch. `StageAnnotation` is handled by: `frozenFrame.value = frozenFrame.value ?: currentFrame.value` (first drag freezes, FR-7/AC-6; subsequent drags find it non-null and only append, FR-31/AC-52), then reduce the annotation in. Reading `currentFrame.value` once, inside the release handler, satisfies AC-47 by construction — there is nothing to buffer because the drag never involved the ViewModel. `sessionDeviceId` is untouched, so the `flatMapLatest` gate keeps the one adb session alive, discovery stays paused (it is gated on the same flag), and `ResumeLive` is `frozenFrame.value = null; reduce { copy(frozen = null) }` — no restart, no first-frame latency, no second session. Cost: `screencap` keeps running behind a static picture; accepted by FR-30 and already logged as a deferred optimisation.

(4) UI — in-progress drag state (`dragStart`/`dragCurrent`) lives in composable `remember`, NOT in Orbit: a pointer move at 60 Hz through the reducer is the same mistake F-2 avoided for frames, and only the committed rect needs to survive the gesture. The stage composes `MirrorFrameView(frame, deviceName) { ... }` with a new optional `overlay: @Composable BoxScope.() -> Unit` slot, so the annotation layer is guaranteed to be exactly coincident with the aspect-fit image (duplicating the aspect-fit maths in the feature module is the single most likely source of a systematic offset). Inside that slot the feature module composes the new kit molecule `AnnotationOverlay(marks, scrim)`: one Canvas that draws the scrim as `clipPath(unionOfMarkRects, ClipOp.Difference) { drawRect(ScrimFill) }` — a single path fill, no saveLayer, no offscreen bitmap, the 1080x2400 ImageBitmap never touched — then one `AnnotationMark` per rect. Live drag = scrim off, one mark in `Drawing` state with its device-px `sizeLabel`, plus `Ruler(totalPx = deviceWidth, extentPx = selection)`. Frozen = scrim on, marks `Pinned`/`Selected`, one `CommentPopover` for the selected mark (wrapped by the host in a `FocusRequester` + `onPreviewKeyEvent` for Enter/Escape — the preview pass reaches an ancestor before the focused BasicTextField, so no kit change is needed), and a `Resume Live` `AppButton` on the stage.
```

### exceptions

- Frame box size is 0 on first composition (before onSizeChanged): FrameGeometry returns an empty rect and the drag layer composes nothing rather than dividing by zero.
- Release with no live frame ever decoded (frame == null): StageAnnotation is dropped, the stage stays live. The Mirror branch already renders nothing until the first frame arrives.
- Sub-minimum drag (a click, or < MIN_DRAG_DEVICE_PX in either axis): discarded, no annotation, no freeze — otherwise every stray click on the stage freezes the mirror.
- Drag starting inside the frame and ending in the letterbox: clamped to the device bounds by toDevice, never negative and never past width/height.
- Delete of the selected annotation: selectedIndex is recomputed (clamped or nulled), never left dangling at a removed index.
- Deleting the LAST annotation leaves the frame frozen with zero annotations (AC-48 explicitly keeps the frozen stage on Clear), so the scrim must handle an empty hole list — it degrades to a plain full dim, which is the honest rendering.
- Session lost (MirrorSession.Lost) while frozen: the frozen frame and its annotations are kept — the user is mid-sentence and the device dying must not erase their work. Resume Live then lands on NoSignal.
- Platform switched to iOS while frozen: selectPlatform already nulls the session; it must also null frozenFrame, or a stale Android frame would sit under the iOS notice.

### edgeCases

- Reversed drag (right-to-left / bottom-to-top) must normalise to a positive rect — tested.
- Host density 2.0 with a frame box whose px size is 2x its dp size: the result must NOT contain a factor of 2 (AC-46 / SC-8 regression).
- Non-integer frame scale (e.g. 1080 device px shown in 713 px of stage): round both corners independently, not the size, so adjacent annotations cannot overlap by a rounding artifact.
- Window or side-panel resize while frozen: marks re-project from stored device px, so they stay glued to the content (free consequence of the canonical space).
- Two annotations with identical rects (double drag in the same spot): both exist, badges 1 and 2, scrim unions them into one hole.
- Escape pressed with no popover focused: must fall through untouched — the device picker's own Escape handler and the shell must still behave (AC-50).
- Cmd+1/2/3 while a comment field has focus: meta-modified, so handleShellShortcut matches and the popover's bare-key handler never sees it (AC-50).
- Typing a digit in the comment field must not switch tabs — same disjointness, verified by the isMetaPressed guard in handleShellShortcut.
- Annotation drawn at the extreme right/bottom: the CommentPopover (min 300 dp wide) would overflow the stage — clamp its x into the stage bounds; the tail currently has a fixed 18 dp inset and will not follow, which is a known demo-fidelity limitation.
- Three annotations stacked vertically within one popover height: triggers FR-9 relocation.
- Resume Live while a comment field has focus and uncommitted text: the text is discarded with the annotation (AC-51 clears everything); no confirm dialog, consistent with AS-13.

### gaps

- No design comp exists for ANY part of this feature — the scrim alpha, the Resume Live control's placement and geometry, the ruler placement, the gutter width, and the leader-line routing are all invented. Every invented value ships as a named private constant so the later design conversation is a one-line change each (the precedent F-1 set with the stage dot grid).
- AnnotationMark's own AnnotationState.Frozen paints an opaque Theme.color.surface fill, which would cover the device pixels the annotation is pointing at. Its KDoc claims Frozen exists 'because the host dims the rest of the frame behind it', but an opaque plate and a visible annotated region are mutually exclusive. Raised as survey item 1.
- CommentPopover's X affordance means DELETE here (FR-8) while Escape means COLLAPSE (FR-29) — two visually similar dismissals with different destructiveness and no confirm. No design input exists on how to signal the difference.
- CommentPopover's tail has a fixed 18 dp inset and no placement logic, so a popover clamped away from its mark's left edge will point at the wrong place. Accepted at demo fidelity; a `tailOffset` parameter is the eventual fix.
- Ruler ships horizontal-only by design ('the vertical ruler is the same strip rotated by the host'). The rotation wrapper (Modifier.rotate plus a layout size swap) does not exist yet — see openDecisions.
- No Compose UI-test harness exists in this repo (zero UI tests, no compose-ui-test dependency), so every AC marked `test` must be satisfiable by a pure/ViewModel test. AC-5 and AC-7 are written as rendering assertions; they will have to be verified as (a) pure geometry + reducer tests plus (b) a preview/demo screenshot. Flag for Stage 3 so the traceability pass does not discover it late.
- StagedAnnotation lives in the presentation contract. F-7 will need it serialized into an MCP payload and F-8 across sessions — that is the moment to lift the model into domain-core, not now.
- SEC-1 (GetProp taking unvalidated free text into adb shell) is NOT touched: this spec reads the device frame's pixel dimensions from the decoded ImageBitmap, never from a device property. No new caller is created.
