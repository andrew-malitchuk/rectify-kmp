### goal

Give a tester one drag gesture on the live Android mirror that freezes the exact frame they saw the bug in, boxes it, numbers it and opens a focused place to describe it — with the box stored in device screenshot pixels so it stays correct across host density, window resize and panel resize. New code is deliberately tiny: one pure geometry function, one kit molecule (the dim scrim), two defaulted kit parameters, and six Orbit intents. Everything visible is assembled from shipped, previewed kit components.

### problemStatement

F-1 (shell) and F-2 (device discovery + live mirror) deliver a live mirror with no way to mark anything on it — a tester can only describe a bug in prose or attach a raw screenshot, which is exactly what this product exists to replace. rectify-poc proved the drag-box interaction is feasible but documented a silent density-conversion bug: pointer events and the composable's own layout are in raw screen pixels, while Modifier.offset/size take Dp which Compose multiplies by density again, so every drawn rectangle lands `density`x from the cursor (2x on this Retina host). Note precisely where that bug lives: on the RENDER leg, not the storage leg. No existing test would catch it. Separately, F-1 shipped three slots reserved for this feature — ShellToolbar.stagedCounter, ShellToolbar.clearAction and SidePanelFrame's Notes tab — as inert stubs, and StatusIndicatorState.Frozen shipped with zero callers. This spec closes the coordinate hole and fills the reserved slots.

### highLevelDescription

Four layers, no new Gradle module, no new catalog entry, no persistence. (1) GEOMETRY — a new internal, pure, non-Composable FrameGeometry in presentation-feature-mirror/core/geometry/, unit-tested BEFORE any UI exists. Pointer offsets from pointerInput and the frame box size from onSizeChanged are in the SAME pixel space, so `devicePx = pointerPx / frameBoxPx * deviceSize` contains no density at all; density applies in exactly one place, converting back out for rendering — which is exactly where the POC's bug lived, so that leg is the one the regression test must exercise. (2) STATE — MirrorUiState gains `frozen: FrozenFrame?` holding a List<StagedAnnotation> and a selectedIndex; the frozen ImageBitmap goes on a second StateFlow beside `frame`, with the reducer storing only its IntSize. Annotations belong IN reduced state for the exact inverse of F-2's reason for keeping frames out: they are a handful of small value-equal records mutated by discrete user actions and read simultaneously by three consumers (toolbar badge, Notes tab, stage marks), whereas frames are identity-compared blobs arriving ten times a second. (3) FREEZE — a render-path switch only. sessionDeviceId and F-2's flatMapLatest capture gate are never touched, so Resume Live costs no new adb session and no first-frame latency; drag-in-progress offsets live in composable `remember` and never enter Orbit. (4) UI — assemble from AnnotationMark, Ruler, CommentPopover, AnnotationPopover, AnnotationRow, CounterBadge, StatusIndicatorState.Frozen and AppButton; author exactly one new kit molecule (AnnotationOverlay = scrim via clipPath(ClipOp.Difference) + one AnnotationMark per rect, fed Dp rects so the kit never converts density itself) and add two source-compatible defaulted parameters to shipped kit components. FR-9's gutter is an in-stage right-edge column, not the Notes tab, because FR-28 already fills that tab.

### architecture

#### approach

Extend presentation-feature-mirror in place across four layers — pure geometry, Orbit state, a render-only freeze, and assembled UI — plus two source-compatible defaulted parameters and one new molecule in presentation-core-ui, and a call-site rewiring in compose-application's RectifyWindow.kt. No new Gradle module, no new Koin module, no persistence, no serialization, no build.gradle.kts edit anywhere.

#### rationale

Every visual element the input artifact called unillustrated already exists as a shipped, previewed kit component except the dim-outside-boxes scrim, small enough to author as one molecule now. This matches the 'assemble, don't author' norm F-1 and F-2 both reached. The coordinate conversion is isolated into one pure internal function because an off-by-density bug there silently corrupts every annotation anchor and no other test would catch it; device screenshot pixels is the canonical space because it is resolution- and window-stable and is exactly what FR-6's label, Ruler's extentPx and F-7's eventual payload need. The conversion is deliberately TWO-legged and both legs are tested: the storage leg (pointer px -> device px) has no density term by construction, and the render leg (frame px -> dp) is the only division by density in the feature — precisely where the POC's bug lived. Freeze-at-release rather than at drag start, because FR-6 frames the drag as happening live, so 'the exact current frame' reads as current-at-release — and reading MirrorViewModel.frame's latest value once inside the release handler needs no buffering, making AC-47 true by construction. Annotations go into reduced state, the opposite of frames, because they are small, value-equal, mutated a handful of times per session and read by three simultaneous consumers. A new presentation-feature-annotation module was rejected: it would need the live frame StateFlow and the stage state from MirrorViewModel, and two ViewModels sharing a bitmap stream is worse coupling than one class with six more handlers, on top of a new convention-plugin wiring and a load-order-significant initKoin entry for a split F-5..F-8 have not yet justified.

#### stateManagement

Orbit MVI in presentation-feature-mirror, four-file convention, existing container. Three tiers by mutation frequency: (1) transient drag offsets live in composable remember and never reach Orbit — a pointer move at 60 Hz through the reducer is the mistake F-2 avoided for frames; (2) pixel blobs (the live frame and now the frozen frame) live on plain StateFlows outside the reducer, preserving deviation 2; (3) semantic state (the staged annotation list, the selected index, the frozen frame's IntSize) lives in MirrorUiState because it is small, value-equal, mutated a handful of times per session and read simultaneously by the toolbar badge, the Notes tab and the stage marks. The frozen bitmap and the frozen reduced state are set inside the same intent, and the render path falls back to the live frame if the bitmap were ever null — one ?:, no sync machinery.

### errorStates

| state | behavior |
| --- | --- |
| empty | Frozen frame with zero annotations (after Clear, or after deleting the last one): the stage stays frozen per AC-48, the scrim degrades to a plain full-frame dim because the hole list is empty, and Resume Live stays visible as the way out. AnnotationOverlay must not build a degenerate Path from an empty list. |
| empty | Notes tab with zero annotations: renders one muted line of empty-state copy (mirror_annotation_notes_empty), never a blank panel. The tab count renders as absent rather than 0 so SidebarTabs does not show a meaningless zero. |
| empty | Annotation with no comment yet: AnnotationRow renders its empty-state copy rather than collapsing, because the mark still exists on the frame and the user needs a way back to it. |
| loading | Frame box size is 0 on first composition, before onSizeChanged reports: FrameGeometry returns an empty rect and the drag layer composes nothing rather than dividing by zero. |
| loading | Session started but no frame decoded yet (frame == null on the Mirror stage): unchanged F-2 behaviour, the stage's dot grid shows. A drag release in this state drops the StageAnnotation intent and the stage stays live — nothing to freeze. |
| error | Sub-minimum drag (a click, or under MIN_DRAG_DEVICE_PX in either axis): discarded silently — no annotation, no freeze. Without this a stray click on the stage freezes the mirror, the worst accidental interaction in a live-mirroring tool. |
| error | Drag starting inside the frame and ending in the letterbox, or a reversed right-to-left / bottom-to-top drag: toDevice normalises to a positive rect and clamps into device bounds, so the stored rect is never negative and never past width/height. |
| error | Delete of the currently selected annotation: selectedIndex is recomputed — clamped into the new range or nulled — never left dangling at a removed index, and the remaining annotations are renumbered so the badges stay 1..N. |
| error | MirrorSession.Lost while frozen: the frozen frame and its annotations are KEPT. The user is mid-sentence and a device dying must not erase their work. The status indicator stays Frozen; Resume Live then lands on NoSignal. |
| error | Platform switched to iOS, or StopMirroring, while frozen: selectPlatform/stopSession already null the session and must also null both the frozen state and the frozen bitmap, or a stale Android frame would sit under the iOS notice. |
| error | An annotation drawn at the extreme right or bottom edge: CommentPopover (PopoverMinWidth) would overflow the stage, so its x is clamped into the stage bounds. ### performanceBudget

| metric | target |
| --- | --- |
| Scrim + overlay draw cost over a live-sized frame | One Canvas, one Path built from at most ~10 rects, one clipPath(ClipOp.Difference) and one drawRect per draw. NO saveLayer, NO offscreen Skia surface, and the ImageBitmap is never read, copied or composited. Budget: at most one extra full-frame-box fill per draw pass — the frame box is the aspect-fit display rectangle (roughly 713x1584 px at the default window on a 1080x2400 device), not the 1080x2400 source bitmap. |
| Path construction per draw | O(n) in the number of annotations, n <= ~10 in practice. Build the union Path inside remember(rects) so a pointer move or a recomposition that does not change the rect list does not rebuild it. |
| Drag feedback latency | The drawn box follows the pointer within one frame (<= 16 ms at 60 Hz). Achieved by keeping dragStart/dragCurrent in composable remember so a pointer move recomposes only the overlay subtree and never passes through the Orbit reducer. |
| Reducer passes per gesture | Exactly one (the StageAnnotation on release). Zero during the drag. This is the invariant that keeps a 60 Hz gesture from becoming 60 state copies a second, mirroring F-2's frame decision. |
| Live mirror glass-to-glass latency (NFR-1) | Unchanged at under ~150 ms. Freeze is render-only — sessionDeviceId and the flatMapLatest gate are untouched — so the capture/decode/transport path has exactly the same cost before, during and after a freeze. |
| Resume Live responsiveness | First live frame visible within one capture interval (~100 ms at the current cadence), with no adb reconnection. This is the whole payoff of the render-only freeze and the headline thing the SC-11 demo checks. |
| Frozen-stage steady-state cost | No per-frame work on the stage while frozen — the static bitmap and the scrim redraw only on recomposition, not on each arriving capture. Accepted cost: the device keeps running screencap behind a static picture (FR-30), logged as a deferred optimisation whose fix would be an isFrozen flag in the transport's adaptive interval, not a session teardown. |
| FR-9 crowding check | O(n^2) pairwise over n <= ~10 nominal rects, recomputed only when the annotation list or the frame box changes — well under a microsecond and explicitly not worth a sweep-line. |
| Memory | At most one extra ImageBitmap alive at a time (the frozen frame), released on Resume Live, platform switch or StopMirroring. No history, no buffering, no serialization (AS-11). |
| Added production code | Roughly 900 added lines or fewer across all four modules. Exceeding that means the reuse-first premise has failed and the plan should be revisited rather than the budget raised. |

presentation-core-ui must not depend on presentation-core-localisation, so AnnotationOverlay and every other kit-level change takes copy as a parameter with an English default and the feature module supplies stringResource(). Machine output — the device-pixel size label and the `218×77 @ 1035,862` meta line — is rendered mono and deliberately carries no resource key, matching how serials, versions and fps are already handled. RectifyWindow.kt's existing literal labels (Clear, Resolve & Send, No device, staged) stay literal: that is F-1's established pattern for that file and converting them is out-of-scope churn; it should be its own small ticket.

### security

#### dataHandling

- Annotations are held in memory only. No disk write, no serialization, no new data module, no file I/O — the POC's JSON writer is F-7's and F-8's business (AS-11).
- The frozen bitmap is a reference to an already-decoded in-memory frame. Nothing new is captured, copied to disk or transmitted.
- Comment text is free user input but never reaches a shell command, a file path or a network call in this spec. It is rendered and held, nothing more.

#### permissions

- No new OS permission, no new adb capability, no new process invocation. The capture loop this spec rides on is F-2's and is unchanged.

#### privacy

- SEC-1 stays closed. Frame dimensions are read from the decoded ImageBitmap, never from GetProp. F-2 left GetProp with zero production callers and NFR-5 holds there only by that absence; this spec creates no new caller — a grep for GetProp must still return zero production hits after this lands.
- No telemetry, no analytics, no crash reporting: a device screenshot and a bug note never leave the host in this deliverable.

### rollout

#### featureFlags

- None. The feature is unconditional once merged — a flag for a desktop developer tool with one user-facing surface would be scaffolding for a rollback that a revert already covers.

#### migrations

- None. No persistence, no schema, no stored preference is added or changed.

#### backwardCompatibility

Every kit API change is a defaulted parameter (MirrorFrameView.overlay, RectifyWindowShell.tabCounts, contingently CommentPopover.focusRequester), so every existing call site, preview and test compiles unchanged. MirrorHost's and MirrorStageContent's public signatures do not change at all. Two user-visible behaviour changes DO land and must be called out in the PR: (1) Cmd+1/2/3 side-panel tab switching becomes live for the first time, because handleShellShortcut only consumed the event while a panel was on screen and the panel was always null; (2) the side panel is now composed permanently rather than never, so the window layout differs from F-1's shipped appearance from the first frame. Both are intended — F-1's own comment says the panel was null only because there was no content, which is precisely what this spec supplies. MirrorStage gaining a Frozen enum entry is source-compatible inside the feature module, and the compiler enforces the new when branch rather than letting it be forgotten. One compile-breaking internal change is NOT backward compatible and must land as a single commit: RectifyWindow.kt's line-129 sidePanel val deletion together with the line-138 isPanelVisible literal.

### openQuestions

- SCENARIO-ID COLLISION (must survive into Stage 5): F-1 already bound SC-3 and SC-4 to different shell scenarios. This spec keeps the PRD's canonical annotation SC-3 (draw and freeze) and SC-4 (crowded popovers relocate). Scenario ids are spec-scoped, not globally unique — do not conflate them when slicing or reporting.
- Whether to pause the capture/transport loop while frozen (power/perf) is left for later — FR-30 assumes it keeps running. If it bites, the fix is an isFrozen flag folded into the transport's adaptive interval, not a session teardown.
- The gutter/leader-line 8 px elbow-stagger polish named in AnnotationPopover's KDoc is not implemented in v1 — a follow-up design/visual-QA pass should revisit it.
- Whether a frozen frame should ever persist annotations across a Resume-Live -> freeze-again cycle (multi-frame annotation sets) is explicitly deferred to F-8 (history).
- Vertical ruler for FR-6's 'ruler/tick guides': this plan takes the recommendation — horizontal plus vertical via the existing Ruler rotated 270 degrees in a fixed-size Box, as the component's own KDoc anticipates, rather than authoring a second VerticalRuler. The rotation wrapper is built in step 6; if rotation produces an unacceptable tick-label orientation, the fallback is horizontal-only, which still satisfies FR-6's wording.
- Where the Resume Live control sits: this plan takes the recommendation — a stage top-right overlay AppButton over the scrim, because the toolbar's primaryAction is reserved for F-7's 'Resolve & Send' and the status bar is only 28 dp tall. The geometry constant is flagged for design review.
- Minimum drag size before an annotation is created: a named MIN_DRAG_DEVICE_PX constant at 8 device px in both axes. A one-line tune, flagged for review after the first real session.
- Does the Notes tab auto-activate on first freeze: surfaced in the survey. The plan's default is auto-select Notes on the FIRST annotation of a frozen frame only, never on subsequent ones, so a user who deliberately switched to Payload is not fought. Implemented in RectifyWindow because ShellState.activeTab has a private setter.
- No design comp exists for ANY part of this feature — the scrim alpha, the Resume Live placement and geometry, the ruler placement, the gutter width and the leader-line routing are all invented. Every one ships as a named private constant so the later design conversation is a one-line change each (precedent: F-1's stage dot grid).
- CommentPopover's X affordance means DELETE here (FR-8) while Escape means COLLAPSE (FR-29) — two visually similar dismissals with different destructiveness and no confirm. No design input exists on how to differentiate them; shipped as-is and flagged.
- CommentPopover's tail has a fixed 18 dp inset (TailInset, line 54) and no placement logic, so a popover clamped away from its mark's edge will point at the wrong place. Accepted at demo fidelity — a tailOffset parameter is the eventual fix.
- StagedAnnotation lives in the presentation contract for now (one consumer, no serialization need); lift it to domain-core only when F-7 needs it in an MCP payload — a package move, not a redesign.
- NEW (plan): making the side panel permanently composed changes the window's appearance from the first frame and activates Cmd+1/2/3 for the first time. Surfaced in the survey. The alternative (session-gated) needs the mirror state inside the Window's onPreviewKeyEvent, where it is not available without a composition-time side effect.
- NEW (refine): AC-47's automatability depends on whether Skiko loads in a headless desktopTest JVM. Resolved by a three-line probe at the top of step 4 rather than by planning both branches in the abstract. The probe result is recorded in the PR and AC-47's verificationNote is updated to match.
- NEW (plan): RectifyWindow.kt's existing literal labels (Clear, Resolve & Send, No device, staged) are left unlocalised, consistent with F-1's choice for that file. Converting them is a separate small ticket, not this spec's churn.
