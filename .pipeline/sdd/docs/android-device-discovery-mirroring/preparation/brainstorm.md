## Data

### highLevelPlan

- Add one typed device vocabulary to domain-core (DeviceModel / EmulatorModel / ToolModel / DiscoveryModel / MirrorStatsModel) plus one new Failure subtype for external-process errors, so F-3 (AC-41/AC-42) inherits a contract rather than a string.
- Add a data-device-api + data-device-impl module pair mirroring the proven data-preference-api/impl shape: API holds the device-scoped command vocabulary and ALL pure parsers (commonMain, unit-testable with no phone); impl holds the only ProcessBuilder in the repo, in desktopMain only, behind an expect/actual Koin provider (FR-1, FR-3, FR-4, NFR-5, AS-7).
- Port rectify-poc's proven logic as pure functions: `adb devices -l` parsing (FR-3), the screencap PNG-signature trim (FR-24), `wm size`/`wm density`/`getprop` reading (FR-22) — logic reused, flat spike structure discarded.
- Express the v1 mirror as `MirrorTransport`: a device-scoped `Flow<MirrorFrame>` plus a stats contract. v1 implementation = screencap polling (FR-24); the scrcpy-server/H.264 implementation is a second class behind the same interface (FR-25) with no UI change.
- Expose discovery as one reactive use case (`Flow<DiscoveryModel>`) driven by a 2s polling flow — no Timer object, no thread, cancellation is structural (FR-5).
- Reuse presentation-core-ui wherever the comps allow (SourceListRow/SourceListHeader, SegmentedButtonGroup, DeviceChip, StatusIndicator, CounterBadge, AppButton, KeyCap, SelectableCard, StatusPill); author only the three surfaces the kit genuinely lacks: the full-stage picker panel, the NO SIGNAL stage, and the mirror frame view.
- Add presentation-feature-mirror (Orbit MVI) holding all state; RectifyWindow injects it and passes plain data + callbacks into RectifyShellContent so that composable stays Koin/AWT/coroutine-free and the render harness keeps working.
- Record the NFR-1 waiver in code and in the UI contract: fps is the real achieved rate, latency is an explicit placeholder, never a fabricated number (AC-45).

### proposedArchitecture

```
One vertical slice through the existing layering, with process execution quarantined in a single desktop-only module.

DATA. New pair `data-device-api` (library+di convention) and `data-device-impl` (library+di), modelled one-for-one on data-preference-api/impl.

`data-device-api` / commonMain, public:
- `@JvmInline value class DeviceId(val value: String)` with a `DeviceId.of(raw): DeviceId?` factory that rejects blank/whitespace/leading-dash values. A deviceId can only be minted by parsing real `adb devices -l` output or by `of()`.
- `sealed interface DeviceCommand { Screencap; WmSize; WmDensity; GetProp(name) }` — a CLOSED set, not a `vararg String`. There is no API in the repo that can run an arbitrary string against a device, which also removes argument-injection as a category.
- `interface DeviceCommandExecutor { suspend fun run(device: DeviceId, command: DeviceCommand): ByteArray }` — every method takes `DeviceId` as a non-optional first parameter, no overload omits it (AC-44).
- `interface AdbHostSource { suspend fun version(): ToolProbe; suspend fun listDevices(): List<DeviceResource> }` and `interface EmulatorSource { suspend fun version(): ToolProbe; suspend fun listAvds(): List<AvdResource>; suspend fun boot(avd: AvdName) }` — the deviceless commands, enumerated explicitly rather than exposed as a generic runner.
- `interface MirrorTransport { fun frames(device: DeviceId): Flow<MirrorFrame>; val stats: StateFlow<TransportStats> }` (FR-25) with `MirrorFrame(bytes: ByteArray, widthPx: Int, heightPx: Int, capturedAtMs: Long)` and `TransportStats(fps: Float, latencyMs: Long?, droppedFrames: Int)` — `latencyMs == null` is the honest 'this transport cannot measure it' signal that AC-45 renders as a placeholder.
- `core/parse/` (internal) + `source/parse/` (public where tested across modules): `parseAdbDevices(stdout)`, `parseWmSize`, `parseWmDensity`, `parseAvdList`, `trimToPngSignature(bytes)`. **All parsing is pure commonMain** — this is the single decision that makes most of the spec testable without hardware (AS-7).

`data-device-impl`:
- desktopMain only for anything that spawns: `core/process/ProcessRunner.kt` is `internal`, is the only file in the repository that names `ProcessBuilder`, and is unreachable from other modules by module boundary + `internal` + `explicitApi()`. It runs in `Dispatchers.IO` via `runInterruptible`, reads stdout and stderr on two concurrent `async` jobs (the poc's deadlock note, kept), enforces a per-call `withTimeoutOrNull`, and in `finally` calls `destroyForcibly()` on a still-alive child. A process-local `Collections.newSetFromMap(ConcurrentHashMap())` of live children plus one `Runtime.addShutdownHook` registered once kills orphans if the window closes mid-capture.
- `core/tool/ToolResolver.kt`: resolves the adb and emulator binaries by probing, in order, `$ANDROID_HOME/platform-tools/adb`, `$ANDROID_SDK_ROOT/...`, `~/Library/Android/sdk/platform-tools/adb`, `/opt/homebrew/bin/adb`, `/usr/local/bin/adb`, then PATH (AS-6). The probed list is carried in `ToolProbe` so F-3's comp-04 footer (`which adb → not found · $ANDROID_HOME unset`) is data, not invention.
- `source/` impls: `AdbHostSourceImpl`, `DeviceCommandExecutorImpl` (always builds argv `[adb, -s, <deviceId>, …]`), `EmulatorSourceImpl`, `ScreencapMirrorTransport`.
- DI: `internal expect fun Module.provideDeviceSources()` in commonMain, desktop actual registering the real impls, android/iOS actuals registering `UnsupportedDeviceSources` (empty lists, `Failure.Technical.Process` on any call) — exactly the `provideSettings()` pattern already in data-preference-impl, so common code still compiles on all four targets.

`data-repository-impl`: `DeviceRepositoryImpl` + `DeviceResourceMapper`/`AvdResourceMapper` in `core/mapper/`, same `ModelResourceMapper` shape as the preference mappers.

DOMAIN. `domain-core` gains `source/model/device/` (`DeviceModel`, `EmulatorModel`, `ToolModel`, `DiscoveryModel`, `MirrorStatsModel`) and `Failure.Technical.Process(cause)`. `domain-repository-api` gains `DeviceRepository`. Use cases (api + impl, every impl body through `resultLauncher(errorMapper = Failure.Technical::Process)`): `DetectToolsUseCase` (FR-1), `ObserveDeviceDiscoveryUseCase` → bare `Flow<DiscoveryModel>` (FR-3/FR-5), `BootEmulatorUseCase` (FR-5/AC-4), `StartMirroringUseCase` → `Flow<MirrorFrame>` (FR-4), `ObserveMirrorStatsUseCase` → `Flow<MirrorStatsModel>` (FR-22). The 2s cadence lives in the repository's polling flow (`flow { while (true) { emit(poll()); delay(2.seconds) } }`), not in a ViewModel timer and not in a `java.util.Timer`.

PRESENTATION. `presentation-core-ui` gains one atom (`RadioMark`, extracted from SourceListRow's private copy so the platform card can reuse it), two molecules (`PlatformToolCard` for comp 01's PLATFORM cards, `EmulatorSelect` for comp 02's inline AVD dropdown), and two organisms (`DevicePickerPanel` for comps 01/03, `NoSignalStage` for comp 02 including the dashed phone outline F-1 deliberately left behind). `presentation-feature-mirror` (feature+di convention) holds `MirrorContract` / `MirrorViewModel` / `MirrorContent` per orbit-mvi.md, with a `MirrorHost` composable in place of the usual `*Screen` (this surface is a shell slot set, not a navigation destination — the deviation is deliberate and documented).

SHELL WIRING. `RectifyWindow` (already a Koin call site) injects `MirrorViewModel`, collects state, and passes `state: MirrorUiState` + `onIntent: (MirrorIntent) -> Unit` + `frame: ImageBitmap?` into `RectifyShellContent`. `RectifyShellContent` keeps zero Koin/AWT/coroutine imports: it only maps data onto slots — `platformSwitch` → SegmentedButtonGroup with the real selection, `deviceIndicator` → DeviceChip with real name/state, statusBar `leading` → StatusIndicator + tool/stat line, `stage` → `DevicePickerPanel` | `NoSignalStage` | `MirrorFrameView` by state. A render harness can still drive it by constructing a `MirrorUiState` literal.

PIXEL PATH. The transport emits PNG bytes; decode happens once per frame on `Dispatchers.Default` in the ViewModel and is published on a dedicated `StateFlow<ImageBitmap?>` — deliberately NOT inside the Orbit state, so 10 frames/s do not push 10 reducer passes and 10 full state copies per second through Orbit. Decode API: `ByteArray.decodeToImageBitmap()` (Compose Multiplatform 1.12, common) with the skiko `Image.makeFromEncoded(...).toComposeImageBitmap()` desktop fallback if the common accessor is not on this module's classpath — verify at plan stage, no new dependency either way.
```

### exceptions

- Missing binary at detection time → NOT an exception: DetectToolsUseCase returns DiscoveryModel.ToolMissing(tool, probedPaths, envHint) as a SUCCESS value so AC-41's typed state and the offline toolbar dot can render. Throwing here would force F-3 to catch rather than read state.
- Missing binary mid-flight (adb disappears after detection, e.g. an SDK update) → java.io.IOException 'Cannot run program' from ProcessBuilder.start() → Failure.Technical.Process(cause); the session stops and discovery restarts, which re-derives ToolMissing on the next poll.
- Non-zero exit (device unauthorized, 'device not found', screencap refused) → ProcessRunner throws DeviceCommandException(argv, exitCode, stderrTail) → mapped by resultLauncher to Failure.Technical.Process(cause). stderr tail is capped (first 2KB) so a chatty tool cannot balloon a log line.
- Timeout → withTimeoutOrNull returns null and the runner raises its own timeout exception → Failure.Technical.Process. Deliberately NOT withTimeout: resultLauncher catches Throwable, so a raw TimeoutCancellationException (a CancellationException) would be converted into a Failure and, worse, the same catch would swallow genuine parent-scope cancellation. Per-call budgets: 3s for discovery/version/info, 5s for a screencap, 0 (detached, untimed) for emulator boot.
- Hung child that neither exits nor writes → the same timeout path, plus destroyForcibly() in finally and removal from the live-child registry. stdout and stderr are drained on two concurrent jobs so a full pipe can never be the reason it hangs (the poc's deadlock note, preserved).
- Parent scope cancelled (window closed, VM cleared) → runInterruptible interrupts the blocking wait, finally destroys the child; CancellationException must propagate untouched, never be mapped to a Failure.
- Device vanishes mid-stream → the capture flow fails with Failure.Technical.Process; F-2 ends the session cleanly, flips DeviceChip to Lost, returns the stage to NO SIGNAL and resumes 2s discovery. Reconnect/recovery UX is explicitly F-3 territory, not built here.
- Boot of an already-running AVD → `emulator -avd X` exits non-zero with a lock-file message; treat as a no-op success (the device is already there and the next poll will show it) rather than surfacing an error.
- Window closes while captures are in flight → shutdown hook destroys every tracked live child. The adb SERVER daemon is intentionally left running; killing it would break other tools on the machine.

### edgeCases

- Packaged .app launched from Finder inherits a minimal PATH (/usr/bin:/bin:/usr/sbin:/sbin) that excludes /opt/homebrew/bin — adb resolves fine under `./gradlew :desktop-application:run` and fails in a real bundle. This is why ToolResolver probes explicit SDK/Homebrew paths before falling back to PATH.
- `adb devices -l` reports states other than `device`: `unauthorized` (prompt not accepted — the exact situation comp 02's step 1 describes), `offline`, `no permissions`, `recovery`, `sideload`. The poc drops them silently; dropping them here would show NO SIGNAL while a phone is plugged in.
- A device appears between two polls while the picker panel is open — the list must update without resetting the highlighted row or stealing a selection the user already made.
- A selected device disappears while the picker is open: selection must fall back to null and Start mirroring must disable, not start against a stale id.
- Running emulator serial `emulator-5554` is not the AVD name the comps show (`Pixel_7_API_34`); mapping requires `adb -s emulator-5554 emu avd name`, which is a device-scoped command and therefore goes through the executor like every other.
- An AVD listed by `emulator -list-avds` is already running — it must appear once (as Running), not twice (once per source).
- Foldables and multi-display devices prepend a warning line to screencap stdout — keep the poc's trim-to-PNG-signature behaviour; it is the single most valuable line in that file.
- `wm size` reports both `Physical size:` and `Override size:` when a size override is set; substringAfterLast(":") picks the override, which is what the mirror actually shows — correct, but worth an explicit test so nobody 'fixes' it.
- Screen rotation mid-session changes frame dimensions; the stats resolution field and the aspect-fit must follow the frame, not a value cached at connect time.
- Screen off / lock screen returns a black or near-empty frame — valid output, not an error.
- Enter on a shut-down emulator row must Boot, not Start mirroring; there is nothing to mirror yet.
- Arrow keys must skip non-selectable rows (unauthorized/offline) rather than landing on a row that Enter cannot act on.
- Escape closes the picker only when a device is already selected; on first run there is nothing behind it, so Escape is a no-op.
- Zero AVDs installed → comp 02's emulator select has nothing to show; the Boot control must disable with an explanatory label rather than opening an empty menu.
- Rapid Start/Stop clicks must not leave two capture loops alive — the session flow is flatMapLatest on the selected device, so the previous loop cancels structurally.
- Switching the platform switch to iOS mid-session: Android capture must stop and the stage must show the deferred-iOS state, not keep streaming behind an iOS-labelled toolbar.
- adb server cold start (first command after boot) takes 1–3s and prints 'daemon started successfully' on stderr — detection must not read that as a failure, and the first poll will be slower than 2s.
- A very large screenshot (tablet/foldable at 2K+) decodes slower than the capture interval; the single-flight guard must drop frames rather than queue them, and the dropped count belongs in TransportStats.

### gaps

- No measured latency number exists yet for either transport. The v1 figure must be measured in step 3; the scrcpy-server/H.264 figure that justifies the v1.1+ follow-up (clarify open question 1) still needs a spike and is NOT answered by this brainstorm.
- resultLauncher catches Throwable, which includes CancellationException — a pre-existing hazard that becomes live the moment this spec introduces long-running cancellable I/O. Mitigated locally by using withTimeoutOrNull, but the helper itself arguably needs a `catch (c: CancellationException) { throw c }` clause. That is a domain-usecase-impl change affecting every existing use case; flagged, not silently made.
- No clipboard abstraction exists for the Copy action in comps 04/05 — F-3's problem, but F-2's ToolProbe must carry the exact command string F-3 will copy, so the data shape has to be agreed now.
- No localisation keys exist for any of this spec's copy ('Choose what to mirror', 'Waiting for an Android device', the two numbered steps, 'NO SIGNAL', the polling footer).
