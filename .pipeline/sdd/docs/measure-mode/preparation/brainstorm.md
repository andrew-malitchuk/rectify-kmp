## Data

### highLevelPlan

- Extend the existing adb plumbing with exactly one new capability: DeviceCommand.UiAutomatorDump (new case in the closed sealed set) plus a pure XML parser in data-device-api/source/parse/, where every other parser in that module already lives so it is testable with no phone attached.
- Carry the dump through the existing one-way data path (DeviceRepository -> DumpHierarchyUseCase -> MirrorViewModel) as a domain HierarchySnapshotModel, and reuse the already-shipped-but-unwired parseWmDensity/DeviceCommand.WmDensity to get the densityDpi that px->dp needs (FR-46, NFR-14).
- Cache the snapshot on a third StateFlow beside MirrorViewModel.frame/frozenFrame, filled once per freeze transition, fire-and-forget, so neither a slow nor a failing dump can block the freeze (AS-18, AC-69, SC-19).
- Put the whole measure algorithm (snap, neighbours, gaps, guide suppression, finding precedence, formatting, px->dp) in internal pure functions under presentation-feature-mirror/core/measure/ — the only layer this repo's test harness can reach (AC-57..AC-66, AC-68).
- Reduce the measure through Orbit: MirrorIntent.StartMeasure(index) on Alt-down computes the readout once and stores MeasureReadout in MirrorUiState; MirrorIntent.EndMeasure on Alt-up appends the Option-prefixed summary to that annotation's note and clears it (FR-43, AC-70, constraint on local Compose state).
- Render from that reduced readout with the three already-shipped, zero-caller components (MeasureCard floating over the stage, MeasureMark Target/Neighbour, MeasureTag for gap numerals) plus one Canvas for the mid-axis guide lines — no component signature changes needed (FR-39, FR-42, AC-67).
- Keep the 60 Hz half (pointer hover position, Alt-held) in `remember` inside MirrorAnnotationStage, exactly as F-4 keeps dragStart/dragCurrent out of the reducer, so Option-hold costs two reducer passes total instead of one per frame.

### proposedArchitecture

```
Four layers, each already grooved by F-2/F-4, and one new pure package.

1. ADB (data-device-api / data-device-impl). `DeviceCommand.UiAutomatorDump` is added to the closed sealed set and gets its argv case in `buildDeviceArgv` -> `["exec-out", "uiautomator", "dump", "/dev/tty"]` (stdout, so no on-device file and no second `adb pull`). `DeviceCommandExecutorImpl.timeoutMs()` gains a branch giving it its own long budget (`MirrorTuning.DumpTimeoutMs`), exactly as `Screencap` has one — the near-miss recorded in error-handling-and-recovery is about precisely this kind of wrong constant. Parsing is `parseUiAutomatorDump(stdout: String): List<HierarchyNodeResource>` in `data-device-api/source/parse/`, because that module's CLAUDE.md makes "every pure parser lives here, in commonMain" load-bearing: it keeps the parser testable from `commonTest` with fixtures and no hardware. It flattens the tree depth-first, reads `bounds="[l,t][r,b]"`, `class`, `resource-id`, `clickable`, tolerates uiautomator's trailing `UI hierchary dumped to: /dev/tty` line and any leading warning line (the `PngTrim` precedent), and returns an empty list rather than throwing on malformed input.

2. DOMAIN. `HierarchyNodeModel` / `HierarchySnapshotModel(nodes, frameWidthPx, frameHeightPx, densityDpi)` in `domain-core/source/model/device/`, with an `Empty` sentinel that is what FR-41's fallback actually reads. `DeviceRepository.dumpHierarchy(deviceId): HierarchySnapshotModel` is a new member on the existing repository (no new repository); its impl in `data-repository-impl` issues the dump and `DeviceCommand.WmDensity` and maps through a one-direction `common-core.Mapper` object in `core/mapper/` — deliberately NOT a `ModelResourceMapper`, because there is no model->resource direction here and mappers.md reserves that pair for round-trips. `DumpHierarchyUseCase` in `domain-usecase-api/source/usecase/device/` returns `Result<HierarchySnapshotModel>` through `resultLauncher(errorMapper = Failure.Technical::Platform)`.

3. PURE MEASURE LOGIC — `presentation-feature-mirror/src/commonMain/.../core/measure/` (internal, per package-layout.md: `core/` is internal-only, and this is the module's third such package after `core/geometry` and `core/annotation`). Nothing here imports Compose beyond `IntSize`, nothing imports Orbit, so every rule in design-measure-mode.md is a `commonTest` assertion — which is the whole reason the split is drawn here and not in the composable. Types: `MeasureNode(id, rect: DeviceRect, isTappable)` (reusing the contract's existing `DeviceRect`, not a second rect type), `MeasureSide` enum (semantics only; the "Size/Top/Right/Bottom/Left" copy is resolved with `stringResource` in the content layer, the `MirrorRow` precedent), `MeasureNeighbours`, `MeasureGaps`, `MeasureUnit { Dp, Px }`. Functions: `snapTarget` (AC-57), `neighboursOf` (AC-58), `gapsOf` (AC-59), `findingOf` (AC-61..64, ordered `when`, single return), `measure(...)` composing them the way the design's own `measure(annotation, unit)` does, `MeasureFormat` (AC-66 / FR-45 — `×`, `Δ` with no space, parens, and the `⌥ ` note prefix), `PixelUnits` (px*160/densityDpi) and `MeasureProjection` (HierarchySnapshotModel -> List<MeasureNode>, the `core/discovery/DiscoveryProjection` precedent).

4. ORBIT + RENDER. The snapshot sits on `MirrorViewModel.frozenHierarchy: StateFlow<HierarchySnapshotModel>`, a third flow beside `frame`/`frozenFrame` — machine output, never a reducer decision, and read with `.value` inside `intent {}` exactly as `stageAnnotation` already reads `currentFrame.value`. It is filled in `stageAnnotation` on the null->set freeze transition via `viewModelScope.launch { dumpHierarchy(id) }` (never awaited) and cleared wherever `currentFrozenFrame.value = null` already happens (`resumeLive`, `stopSession`, `selectPlatform`) — which answers clarify's open question: one dump per freeze, re-dumped on a new freeze after Resume Live. Reduced state gains `measure: MeasureReadout?` and `hierarchyStatus: HierarchyStatus { Absent, Dumping, Ready, Unavailable }`; intents gain `StartMeasure(index)` and `EndMeasure`. `StartMeasure` runs `measure(...)` once and reduces; `EndMeasure` reduces the note append and nulls the readout. Two reducer passes per Option-hold. In `MirrorAnnotationStage` the hover offset and the Alt-held flag live in `remember` (the dragStart/dragCurrent discipline); the measure overlay is a sibling layer inside the same frame-sized Box as `AnnotationOverlay` so every coordinate still goes through the one `FrameGeometry`; `MeasureCard` floats in the stage's outer Box aligned TopStart with a spacing token, the slot the drop banner and Resume Live already use. None of `MeasureCard`, `MeasureMark`, `MeasureTag` needs a signature change: the 228 px design width is `Modifier.width(...)` passed in ahead of the card's own `widthIn(max = 360.dp)`, the `⌥` keycap and "Measuring" title are already in the header, and the finding block already renders `Theme.color.annotate` at 10% over surface.
```

### exceptions

- Dump exits non-zero, times out, or the device vanishes mid-dump: DumpHierarchyUseCase returns Failure.Technical.Platform; the ViewModel takes getOrNull(), stores HierarchySnapshotModel.Empty, reduces hierarchyStatus = Unavailable, and the freeze is already done (AC-69, NFR-14, SC-19).
- Dump succeeds but stdout is not parseable XML: parseUiAutomatorDump returns an empty list rather than throwing (the PngTrim never-throw precedent), which is indistinguishable downstream from an empty hierarchy and lands on the same FR-41 fallback.
- `wm density` fails or parses to null: densityDpi is unknown, the readout is emitted in MeasureUnit.Px and every value is labelled `px` rather than printing dp numbers computed from a guessed density (the design's own units table admits `1344 px`).
- adb binary missing at dump time: ToolResolver throws DeviceCommandException inside the use case, mapped to Failure.Technical.Platform; same handling as above, no new UI path.
- Dump geometry does not match the frozen frame (rotation or an override resolution changed between capture and dump): MeasureProjection discards the snapshot and reports Unavailable instead of measuring against coordinates from a different screen.
- Option pressed with no annotation under the cursor: the hit-test returns null, no intent is dispatched, nothing renders. Not an error state and not a reduced flag.
- Option released while the window is not focused (Cmd-Tab, release outside the window): EndMeasure is dispatched from onFocusChanged as well as from KeyUp, so the panel can never stick.
- A new pointer-down or drag start while measuring: EndMeasure is dispatched first, so the measurement persists and the overlay does not survive into the next gesture.
- StartMeasure arrives for an index that no longer exists (deleted between hover and key-down): the reducer returns state unchanged, the same `?: return@reduce state` guard every other annotation handler uses.
- The annotation's note already carries an ⌥ line from a previous hold: EndMeasure replaces that line instead of appending a second one, so repeated holds cannot grow the note without bound.

### edgeCases

- Option pressed with no annotation under the cursor -> no-op (no panel, no state change). Resolution chosen over 'measure the selected annotation' because measuring a box the pointer is not on is a surprise, and the design's trigger is explicitly positional.
- Option held while a new box is still being dragged (FR-44 says 'staged or in-progress') -> proposed: ignore Alt until the drag is released, because measuring a live drag rect means recomputing the readout per pointer frame, which is precisely the 60-Hz-into-the-reducer pattern F-4 forbids. This narrows FR-44's wording and is survey question 1.
- Multiple overlapping annotations under the cursor -> the highest index wins (last staged, topmost drawn). A pure `annotationAt(point, annotations)` function in core/measure/, so the tie-break is asserted rather than implied by iteration order.
- Option released outside the window / focus lost -> EndMeasure on focus loss as well as KeyUp; the measurement still persists to the note, because a release the host did not see must not silently discard the user's measurement.
- Dump still in flight when Option goes down (the ~2.6 s window after freeze) -> hierarchyStatus = Dumping; the card reports the dump as pending and the readout uses the FR-41 fallback. Survey question 2 — the honest alternative is a plain '(no match)' that will start working a second later for no visible reason.
- Hierarchy describes a different orientation or resolution than the frozen frame -> discarded, Unavailable, fallback. Detected by comparing the dump's root bounds against FrozenFrame.deviceSize on both axes.
- densityDpi unknown -> MeasureUnit.Px throughout, including the touch-target finding, which therefore cannot fire (it is defined in dp); no finding is better than a finding computed from a guessed density.
- Guide gap converts to less than 1 dp but is 2 px -> suppressed, because suppression is evaluated in the display unit after conversion (FR-39/AC-60: 'never rounded up and never shown as zero').
- Alignment tolerances (±10 / ±24) stay in device pixels while the delta they report is formatted in dp — the design states them on raw coordinates and AC-61/AC-62 repeat the px figures. Converting the tolerance would silently change which findings fire on a 3x device.
- A Compose-only app under test: uiautomator reports real bounds but mostly empty resource-id, so node ids degrade to class names. Formatting must handle an empty resource-id (`android.view.View` with no `#suffix`) rather than emitting a dangling `#`.
- A scrolling list: off-screen nodes are not in the dump, so a side legitimately has no neighbour and the gap is measured to the frame edge — already FR-38's rule, no special case.
- FLAG_SECURE or a system dialog on top: the dump can be empty or describe the overlay rather than the app; indistinguishable from a failure and handled as one (fallback).
- An annotation drawn partly in the stage letterbox: FrameGeometry.toDevice already clamps to the device bounds, so the measured rect always exists on the device.
- The selected annotation's CommentPopover sits over the measured node and its guides -> while state.measure != null the anchored/gutter/selected popovers are suppressed, so the measurement is readable; they come back on release.
- A second freeze after Resume Live -> hierarchy is cleared with the pinned bitmap and re-dumped on the next freeze transition. This answers clarify's open question about re-freeze directly.
- Zero-area or 1-px annotation: cannot reach StageAnnotation (MIN_DRAG_DEVICE_PX = 8 in both axes), so snapTarget never sees a degenerate rect from the UI; the function still handles it for the unit tests.
- Option held on a frame that was never frozen (live stage): measure requires FrozenFrame, so Alt over the live stage is ignored — there is no cached hierarchy and no annotation to measure.

### gaps

- No hierarchy source exists today at all: DeviceCommand has no dump case, nothing shells out to uiautomator, and no node type exists in any module. Everything in layer 1 and 2 is new code, not wiring.
- Density is not plumbed anywhere. parseWmDensity, DeviceCommand.WmDensity, DeviceCommand.WmSize and DeviceInfoResource all exist, are tested, and have ZERO production callers — grep confirms the only references are their own tests. px->dp therefore depends on wiring dead scaffolding, which is cheap but is real work nobody has done.
- uiautomator's node id format is undefined by this spec. The design's `TextView#item_price` is class-simple-name + '#' + resource-id short name; nothing says what to emit when resource-id is empty (common on Compose surfaces) or when two siblings collide.
- No Compose UI-test harness, so AC-67/AC-69/AC-71 and all overlay geometry are demo-verified only (already accepted in outOfScope). The architecture compensates by pushing everything assertable below the Compose layer, but guide placement itself stays unproven by any test.
- 'tappable' is not defined by the requirements. Proposed: uiautomator's `clickable="true"`, optionally OR'd with `long-clickable`/`focusable`. AC-63's touch-target finding only fires for tappable nodes, so this predicate decides whether that AC is ever observable.
- The ~2.6 s post-freeze window where no hierarchy exists is not covered by any AC. AC-69 covers failure, not pendency, and SC-19 is the failure scenario.
- Whether the appended note line is localised is still open (clarify's own open question). Proposal: unlocalised, like CommandBlock's machine output — it is numeric machine text destined for an agent prompt, and localising `Δ6dp vs item_title` would make the payload locale-dependent.
- No fixture of a real uiautomator dump exists in the repo. Someone with the reference Pixel 8 has to capture two or three (a View-based app, a Compose app, a scrolling list) before the parser can be tested against reality rather than against a hand-written guess.
- `uiautomator dump /dev/tty` is not universally available (older API levels, some OEM builds write only to a file). No fallback path (`dump /sdcard/x.xml` + `cat`) is specified; proposed to leave it out and degrade, but that is a decision, not an oversight.
- There is no measurement of how much a concurrent dump costs the running capture loop. The transport counts dropped frames, so the number is observable, but nobody has observed it.

### risks

| text | likelihood | impact | mitigation |
| --- | --- | --- | --- |
| The dump is the whole feature's input and its reliability is unmeasured on real hardware: `uiautomator dump /dev/tty` can be empty on a secure window, truncated under memory pressure, slow enough to miss its budget, or absent on older/OEM builds. If it typically returns nothing useful, every measure degrades to 'View (no match)' and the feature ships as a fallback. | med | high | Make the fallback first-class and honest (FR-41 + hierarchyStatus reporting Dumping/Unavailable), never-throw parsing, its own timeout, and a hardware spike BEFORE Stage 4 that captures three real dumps as commonTest fixtures. If the spike shows /dev/tty is unreliable, the file+cat fallback becomes a plan task rather than a surprise. |
| px->dp conversion is built on dead scaffolding: densityDpi has no production caller today, so a wrong or missing density silently multiplies every number in the panel by ~2.6x on a 420 dpi device — and a confidently wrong number in an agent prompt is worse than a prose estimate, which is the feature's entire justification. | med | high | Read density with the dump in the same repository call; treat unknown density as MeasureUnit.Px and label it px rather than guessing; unit-test toDisplayUnit against known pairs (420 dpi: 1080 px = 411 dp); have the demo for AC-67 state the device's dpi so a reviewer can check one number by hand. |
| Alt key-up may never reach the app. onPreviewKeyEvent needs focus, the stage root does not currently request it, and Compose Desktop does not deliver key events to an unfocused window — so a stuck Measuring panel with a stale readout is a plausible failure, and the note append (AC-70) would never fire. | med | med | Request focus on the stage root (DevicePickerPanel precedent), dispatch EndMeasure from onFocusChanged and from the next pointer-down as well as from KeyUp, and treat 'Alt not pressed' on any arriving pointer event's keyboardModifiers as a release. Verify by manual demo early — this is exactly the class AS-21 assumes away. |
| The freeze-time dump runs while the capture loop is still streaming (FR-30 keeps it alive), so two adb children contend for one device; the measured 2665 ms screencap gets slower and the single-flight transport counts dropped frames, visibly degrading fps right when the user freezes. | med | med | Open decision below (pause the loop for the dump vs accept the dip). Either way the dip is bounded to one dump per freeze, and the user is looking at pinned pixels, not live ones. Instrument via the existing TransportStats drop counter. |
| On a Compose-built app the dump's resource-ids are mostly empty, so node ids become `android.view.View` repeated dozens of times. The snap still works geometrically, but the panel's node id and the finding copy ('vs {id}') lose their meaning — the panel looks broken while being correct. | med | med | Fall back to class-simple-name plus a disambiguating index, and include a Compose-app dump among the parser fixtures so the degraded label is a deliberate, tested string rather than an accident. |
| A hand-rolled XML scanner in commonMain mishandles real-world attribute content (escaped entities, '>' inside a content-desc, self-closing vs nested nodes), producing wrong bounds rather than no bounds — a silent wrongness the never-throw contract cannot catch. | med | med | Parse only the four attributes the feature needs, drive the bounds regex off a strict `[l,t][r,b]` shape and skip any node whose bounds do not match, unescape the five XML entities explicitly, and fixture-test against real dumps including one with a quote and an ampersand in content-desc. |
| Guide geometry and panel fidelity (AC-67) have no automated check anywhere in the repo, so a mid-axis guide drawn in the wrong coordinate space (the exact bug class FrameGeometry's KDoc records from the proof-of-concept, where a stray density division halved every mark on Retina) can only be caught by eye. | med | med | Route every measure coordinate through the one FrameGeometry with no second conversion, keep the overlay inside the same frame-sized Box as AnnotationOverlay, and ship light/dark @Previews of a measuring frozen stage as the review artifact. |
| Scope creep in the reducer: measure state, hierarchy status, the note append and the existing annotation handlers all mutate the same FrozenFrame, and MirrorViewModel is already ~470 lines with a documented race hazard about reading state outside `reduce`. | low | med | Follow the module's existing rule literally — every new handler reads state.frozen INSIDE reduce — and keep both new handlers to one reduce each. MirrorViewModelAnnotationTest already covers the race precedent; extend it rather than writing a new pattern. |
| Repeated Option-holds append repeated ⌥ lines, so a note that is sent to the agent carries three contradictory measurements of the same box. | med | low | EndMeasure replaces an existing ⌥-prefixed line for that annotation instead of appending; covered by a reducer test. |

### openDecisions

| decision | options | recommendation |
| --- | --- | --- |
| Does Option during an in-progress drag enter measure mode (FR-44 says 'staged or in-progress')? | ["Ignore Alt while a drag is in flight; measure only committed annotations", "Measure the live drag rect, recomputing the readout locally (outside Orbit) on each pointer frame", "Measure the live drag rect through the reducer on every pointer frame"] | Ignore Alt while a drag is in flight. The third option is the 60-frames-per-second-of-state-copies pattern F-4 explicitly forbids; the second keeps it out of Orbit but then the readout lives in two places and AC-70's note append has no committed annotation to write to. Narrowing FR-44 to 'staged' costs one word and keeps one state home. |
| What does the panel show while the freeze-time dump is still in flight (~2.6 s)? | ["Report it: hierarchyStatus = Dumping, the card says the hierarchy is still being read, values use the FR-41 fallback", "Say nothing: plain 'View (no match)' until the dump lands", "Block Option-down until the dump completes (await with a short budget)"] | Report it, reusing the already-shipped StatusIndicator 'Dumping' state. Option 2 lies for two seconds and then silently starts working; option 3 puts an adb child on a key press's critical path, which is precisely what NFR-13 excludes. |
| Does the freeze-time dump pause the capture loop? | ["No: accept a transient fps dip while two adb children contend for the device", "Yes: suspend the transport for the duration of the dump, then resume", "Only pause when the session is Streaming and the frame is already frozen"] | No, for v1. The user is looking at pinned pixels during the dump, FR-30 deliberately keeps the loop alive so Resume Live costs no reconnection, and pausing adds a transport state nothing else needs. The existing dropped-frame counter makes the cost measurable, so this can be revisited with a number instead of a guess. |
| Is the ⌥ note line localised? | ["Unlocalised machine text, like CommandBlock's output", "Localised through presentation-core-localisation"] | Unlocalised. The line is numeric machine output destined for an agent prompt; localising it would make the sent payload locale-dependent, and localisation.md already reserves this treatment for machine text (serials, versions, adb command lines). |
| What is 'tappable' for AC-63's touch-target finding? | ["uiautomator clickable=\"true\" only", "clickable OR long-clickable OR focusable", "clickable OR a class-name allowlist (Button, ImageButton, ...)"] | clickable="true" only. It is the one attribute that means 'the app installed a click listener'; the broader predicates fire on scroll containers and text fields and would make the <32 dp finding noisy, and AC-63 is a 'should'. |
| Node id format when resource-id is empty (Compose surfaces) | ["Class simple name alone (no '#')", "Class simple name + a sibling disambiguation index", "Keep the fully-qualified class name"] | Class simple name plus a sibling index when two siblings would otherwise collide — the panel's node id and the finding's 'vs {id}' both have to identify something a human can find again, and `android.view.View` repeated four times identifies nothing. |
