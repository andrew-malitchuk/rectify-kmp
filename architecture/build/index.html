Architecture

Build and testing

One target#

Every module applies kotlin("jvm"). There is no Kotlin Multiplatform plugin, no platform targets, no expect/actual, and sources sit in the classic src/main/kotlin and src/test/kotlin.

Compose Multiplatform is still used — for the renderer and the component library, not for multiplatform reach.

Adding a platform is a migration back to KMP, not a flag: re-add the plugin in the convention plugins, split src/main into commonMain plus a platform source set, and add a runnable module for the new platform.

Convention plugins#

Four, in build-logic/convention, all extending BaseConventionPlugin — a template method over three hooks, run in a fixed order: configurePlugin → configureJvm → configureDependencies.

java-library is applied explicitly because kotlin("jvm") alone does not guarantee the api configuration, and several modules use api(projects.x).

compose.desktop.currentOs — the Skiko renderer — is only on the application plugin. Only the module that actually opens a window needs it.

Three modules skip convention plugins entirely: desktop-application, data-mcp-impl and docs-generator. Each is a binary with its own deliberately minimal classpath, not a library in the app's dependency graph. This is documented rather than accidental — do not "fix" it by inventing a fifth plugin for a module count of one.

Commands#

./gradlew :desktop-application:run        # run the app
./gradlew build                           # compile everything and run every test
./gradlew :presentation-core-ui:test      # one module
./gradlew generateDocs                    # render this site into docs-generator/build/docs-site

./gradlew build is the honest "everything passes" command: one target means no cross-target compile step and no separate test invocation to forget.

Testing#

kotlin.test is wired once, in the library and feature convention plugins. Never add kotlin-test module by module.

A module may still declare a test dependency of its own when the need is genuinely local — data-preference-impl adds multiplatform-settings-test because only it fakes a settings backend. The rule is about the shared harness, not about banning local fixtures.

What is worth testing#

Pure, side-effect-free logic first. That is where the suite actually lives: parsers, clampPanelWidth, shortcutToTab, state transitions, mapper round-trips, the verify arithmetic, column-width geometry.

Do not add a test per *UseCaseImpl by rote. They are thin wrappers around a repository call. Test one directly only when it has branching logic of its own.

A convention worth copying#

Assertions compare lists of labelled strings, so one failure reports every relevant field instead of stopping at the first mismatch:

assertEquals(
    expected = listOf("idBefore=PIXEL-9", "id=null", "dismissable=false"),
    actual = listOf(
        "idBefore=${before.selectedDeviceId}",
        "id=${after.selectedDeviceId}",
        "dismissable=${after.isPickerDismissable}",
    ),
)

Several tests also carry a MUTATION: note naming the edit that should break them. It is a cheap, checkable claim that the test tests something — and it is checked, by making the edit and watching it fail.

Documentation#

This site is generated by :docs-generator from Markdown in docs/:

docs/
├── site.json          # nav manifest — order and titles are editorial
├── content/           # the Markdown, one file per page
└── assets/            # stylesheet, search script, icon

Content stays in Markdown as the single source of truth; the generator renders it with the app's design tokens. ./gradlew generateDocs writes docs-generator/build/docs-site/, and a GitHub Actions workflow publishes it to Pages on every push that touches docs/ or the generator.

Preview it locally with any static server — the default build uses root-relative URLs, which file:// cannot follow:

./gradlew generateDocs
python3 -m http.server -d docs-generator/build/docs-site 8000

CI passes the real base path (-PdocsBaseUrl=/rectify-kmp), derived from the repository name so a rename does not silently 404 every stylesheet.

To add a page: write the Markdown under docs/content/, add an entry to site.json. The generator fails loudly if a manifest entry points at a file that does not exist.
